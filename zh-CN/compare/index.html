CAPROVER 与其他方案对比

选择适合你的自托管 Docker 工作流。

使用 CapRover，可以从终端上传代码，再从应用面板管理对应的 Swarm 服务。看看这种方式与在 Git 中维护 Compose 文件或通过 SSH 管理多台服务器有何不同。

同一个 Dockerfile，两次部署

照片应用的 Dockerfile 需要复制项目源码。平台安装完毕后，怎样发布第一版？改完代码后，又怎样发布第二版？

CapRover

发布第一版
创建 Web 应用并用 caprover login 登录。提交指向 ./Dockerfile 的 captain-definition，运行 caprover deploy 并选择应用和分支。VPS 会用上传的提交构建镜像。
更新代码后
提交修改后，在同一目录运行 caprover deploy -d 即可沿用上次的部署选项。域名和 HTTP 设置仍由该应用管理。
CLI 部署指南

Coolify

发布第一版
将项目推送到 Git 仓库。在 Coolify 的项目和环境中，从该仓库创建应用，选择分支和 Dockerfile 构建方式，再部署。COPY 所需的文件来自检出的仓库。
更新代码后
推送到该分支后重新部署，也可以启用自动部署。使用支持预览的 Git 集成时，拉取请求可以获得独立的预览地址。
Dockerfile 部署指南

Dokploy

发布第一版
在项目环境中创建 Application，选择 Dockerfile 构建方式并指定路径，然后使用 ZIP 上传方式，从电脑部署项目目录。
更新代码后
向同一应用上传新的 ZIP。若习惯推送提交，可改用 Git 源；若整套服务的定义也要放在仓库中，可以使用 Compose 资源。
应用来源与 ZIP 上传
1 GiB

适合小型服务器

CapRover 要求至少 1 GiB 内存和 5 GiB 可用磁盘。Coolify 列出 2 GB 内存、2 核 CPU 和 10 GB 可用磁盘，预算有限时也建议考虑 1 GB 内存。这些是安装配置，构建和运行应用还需要预留资源。 Dokploy 建议使用 2 GB 内存和 30 GB 磁盘。

以上为官方公开的安装要求，并非运行时基准测试。请根据实际应用、构建任务和存储需求规划服务器规格。
