CAPROVER 与 DOKKU 对比

获得完整的开源控制面板，同时保留命令行。

CapRover 让常规路径直观而简单，同时在需要时提供 CLI、API、NGINX 和 Docker 控制能力。你无需在易用性和基础设施访问之间二选一。

为什么选择 CapRover

如果你希望开源产品包含控制面板操作、一键应用、回滚和多节点编排，请选择 CapRover。如果 CLI 优先的工作流、广泛的构建器选择、cron 和可组合插件系统是核心要求，请考虑 Dokku。

控制面板是简单路径

无需拼装命令即可查看和编辑域名、证书、环境变量、持久化目录、副本、日志和部署历史。

这让每个能够访问 CapRover 控制面板的开发者都能轻松完成日常操作。

命令行依然可用

从本地项目运行 caprover deploy，上传归档，部署镜像，或触发通用 Git Webhook。控制面板本身使用 CapRover 的 HTTP API。

CapRover 增加了可视化工作流，同时不影响自动化或基于终端的部署。

简单不代表受限

大多数应用直接使用生成的 NGINX 和 Docker 配置。高级负载可以编辑完整的按应用 NGINX 模板，并覆盖原生 Docker 服务设置。

在操作员明确需要之前，这些控制不会出现在常用路径中。

实际差异

Dokku 的开源核心有意采用 CLI 优先，并通过构建器、命令和插件实现高度可组合。Dokku Pro 另行提供官方 Web 界面和 API。

CapRover 直接在开源平台中提供可视化操作工作流、一键目录和 Swarm 管理。

为什么选择 CAPROVER

  • 开源平台应包含完整的 Web 控制面板。
  • 你希望同时拥有简单的可视化工作流和直接本地部署。
  • 你希望可以使用深度 NGINX 和 Docker 控制，但不让它们成为默认工作流。
  • Docker Swarm 集群和回滚应通过同一产品管理。
  • 你依赖一个包含可部署应用和数据库的一键目录。

何时更适合选择 Dokku

  • SSH 命令和 Git push 应作为主要界面。
  • Buildpacks 和可组合插件系统不可或缺。
  • 你需要内置 cron 任务定义或全局环境变量。

迁移到 CapRover

将 Dokku 配置转换为 CapRover 环境变量和应用设置，添加 captain-definition 文件，映射域名，并使用数据库自带的备份和恢复工具迁移数据存储内容。
