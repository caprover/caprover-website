应用配置参考

CapRover 将应用设置与 Captain Definition 分开保存。应用数据模型包括：

分类保存的字段作用
应用身份projectId、description、tags项目组织与标签。
部署deployedVersion、versions、captainDefinitionRelativeFilePath部署历史与定义文件路径。
HTTPnotExposeAsWebApp、containerHttpPort、forceSsl、hasDefaultSubDomainSsl、websocketSupport、customDomain、redirectDomain、httpAuth、customNginxConfig路由和访问控制。
节点调度hasPersistentData、nodeId、instanceCount、networks持久化和 Swarm 调度。
运行时envVars、ports、volumes、serviceUpdateOverride、preDeployFunction环境变量、发布端口、挂载和高级配置。
  • 环境变量以 {key,value} 键值对保存。
  • 发布端口包含 hostPort、containerPort、可选的 protocol（tcp 或 udp）以及可选的 publishMode（ingress 或 host）。
  • 持久化目录包含 containerPath，可选的 hostPath 或 volumeName，以及可选的 mode。
  • 应通过 dashboard 或 API 修改这些配置，不建议手动编辑存储的 JSON。

默认值与限制​

以下是 CaptainConstants.ts 和 EnvVars.ts 中的部分默认值：

配置项默认值
CapRover 状态目录/captain；备份数据位于 /captain/data
宿主机 HTTP、HTTPS 和管理端口80、443、3000
dashboard 子域名captain
API 版本v2
Docker 日志默认大小512m
构建日志行数和应用日志 tail 行数分别为 50 和 500
保存的部署版本上限50
Docker 构建版本选择器2
关闭定时镜像清理时的保留数量1

以上是源码默认值，不保证每个实例都使用相同配置。默认值可能被覆盖，也可能随版本变化。自动化前请核对实际版本与对应源码。

旧版兼容性​

  • CapRover 保留了前身 CaptainDuckDuck 的部分历史命名和链接。

  • 当前预览阶段仍保留已有的 /docs/* 路径。旧路径与新路径的映射参阅草案 URL 对照表。

  • 重定向会在后续正式切换时处理。

  • Captain Definition 解析器支持 schemaVersion: 2。

  • 旧定义可能需要迁移；参阅从 CaptainDuckDuck 迁移。

  • 对 CapRover 1.15.0 之前创建的应用，模型保留了 isLegacyAppName 字段，可能影响 service 命名兼容性。

  • 修改写死的内部主机名之前，请阅读内部网络。

预览阶段应保留已有 URL 与旧 service 别名。正式切换时逐一验证历史链接和已经部署的应用。
