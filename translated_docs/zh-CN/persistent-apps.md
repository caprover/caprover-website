### 持久化应用与非持久化应用

创建应用时，可以选择它是否应拥有**持久化数据**。  
默认情况下，为了更好的灵活性和可扩展性，应优先选择**非持久化应用**。不过，当应用需要在容器重启、崩溃或更新后保留数据时，就需要持久化。

如果你有大量静态数据，不想把它们打进每次构建，也可以把主机上的目录映射到容器内的目录。除非数据非常大，否则通常不需要这样做。

---

#### 持久化应用

持久化应用需要把数据存在磁盘上，以便在重启、崩溃、容器更新和其他事件后仍然保留。因为它们把数据存在本地，所以会**锁定到特定服务器**。你可以把它移到另一台服务器，但除非你手动迁移，否则已存储的数据会丢失。

**需要持久化的应用示例：**
- 数据库（例如 MySQL、PostgreSQL、MongoDB）
- 把图片存在本地、而不是使用第三方存储（例如 S3）的图片上传应用
- 像 WordPress 这样把上传文件或插件存在磁盘上的 Web 应用

**限制：**
- 持久化应用**不能**扩展到多个实例。  
  在多个容器之间共享同一个存储路径可能导致数据损坏。

> **注意：**  
> 即使是持久化应用，**也不是所有目录默认都持久化**。创建应用后，必须在控制台的 **App Details** 页面明确指定哪些目录应持久化。

---

##### 定义持久化目录

你可以用两种方式配置持久化目录：

**1. 使用标签（推荐）**  
由 CapRover 管理存储位置。  
- 数据保存在：  
  `/var/lib/docker/volumes/YOUR_VOLUME_NAME/_data`
- 容器路径可以自定义。
- 默认情况下，CapRover 会在卷名前面加上 `captain--`。  
  例如，输入 `my-volume` 会得到 `captain--my-volume`。

**2. 使用特定主机路径**  
你可以把**主机上的特定目录**映射到容器内的路径。  
例如：  
- 主机路径：`/var/usr`
- 容器路径：`/my-host-usr-something`
  
保存在容器 `/my-host-usr-something/myfile.txt` 的文件，可以在主机 `/var/usr/myfile.txt` 访问。

> **重要：**  
> 如果你选择特定主机路径，请确保在分配之前，该目录**已经存在于主机上**。

---

#### 删除持久化应用

删除持久化应用时，它的数据**不会自动删除**。这是为了防止意外丢失数据。要删除持久化目录：

- **卷（基于标签）**  
  1. 列出卷：  
     ```bash
     docker volume ls
     ```
  2. 删除目标卷：  
     ```bash
     docker volume rm NAME_OF_VOLUME
     ```

  ![Volumes](/img/docs/label-path.png)

- **映射的主机目录**  
  直接从主机删除目录：
  
```bash
  rm -rf /path/to/directory
```

![mapped](/img/docs/path-binding.png)

#### 非持久化应用

**不需要把数据存在磁盘上**的应用应始终设为非持久化。
它们更灵活，如果某台服务器不健康，可以自动迁移到其他服务器。

**非持久化应用的优势：**

* 可以运行多个实例而不会冲突（存储是隔离的）
* 在多服务器环境中会自动重新部署到其他服务器

> 非持久化应用**仍然可以写磁盘**，但容器因崩溃、部署、配置更新或主机重启而重启时，这些数据会丢失。

**示例：**

* 分析上传照片的图片处理器（无状态且消耗 CPU）
* TODO Web 应用：数据库是持久化的，但 Web 应用本身不在本地存数据
* 使用 S3 或其他第三方存储、而不是把图片存在本地的图片上传应用
