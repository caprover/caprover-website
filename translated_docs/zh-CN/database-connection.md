<br/>

你作为[一键应用](one-click-apps)部署的所有数据库，都会作为 Docker 容器部署。每个容器的名称都以 `srv-captain--` 为前缀，以避免与同一主机上可能运行的其他容器冲突。所有容器都可以通过 Docker overlay 网络互相通信。网络架构类似这样：


```bash
          Outside World
              +
              |
+---------+---+---+-----------------------------+
|         |       |                             |
|         | NGINX |                             |
|         |       |                             |
|      +--+-------+---+                         |
|      |              |                         |
|      |              |                         |
|  +---v--+     +-----v+      +-----------+     |
|  | App1 |     | App2 +------> Database1 |     |
|  +------+     +------+      +-----------+     |
|                                               |
+-----------------------------------------------+
```


### 内部连接

最简单的连接类型，是从上面图中的 `App2` 连接到 `Database1`。这时，你只需连接到 `srv-captain--database1` 并指定端口。不需要端口映射或额外配置。代码看起来会像这样：

```
databaseEngine.connect(
    {
        host: srv-captain--database1,
        port: 5000
    }
)
```


### 外部连接

**重要** 如果你在外部连接上遇到问题，很可能是配置不正确。CapRover 经过充分验证，可以保证工作。见[这里](https://github.com/caprover/caprover/issues/364)列出的一些常见错误。

有时，你需要从外部世界连接到数据库。这时有两个选择：

1) 端口转发
这是最简单的方案。你只需打开 CapRover 的 App Config 页面，把一个任意主机端口映射到数据库端口。例如，默认 MySql 端口是 `3306`，你可以把主机端口 `12345` 映射到容器端口 `3306`，然后从本机做类似这样的操作：

```
databaseEngine.connect(
    {
        host: <ip address of your CapRover server>,
        port: 12345
    }
)
```

确保在防火墙中放行主机端口。否则你将无法连接到数据库。


2) SSH 隧道
这种方法更高级。要这样做，你首先需要部署一个 SSH 一键应用。你可以在 CapRover 实例的官方一键应用列表中选择它。确保选择一个足够长且安全的密码。安装过程中，系统还会要求你提供一个端口来映射这个 SSH 镜像。默认使用端口 `4646`。确保这个端口已在防火墙中放行。这个新镜像部署完成后，你就可以从本机运行下面的命令：
```
ssh -L 8181:srv-captain--mysql:3306 root@<ip of your CapRover Server> -p 4646
```

这会把本机端口 `8181` 映射到 MySQL 容器端口 `3306`。现在，你可以从本机运行类似这样的代码：
```
databaseEngine.connect(
    {
        host: localhost,
        port: 8181
    }
)
```
**重要：** 你不能通过服务器上的常规 SSH 对数据库做 SSH 隧道。你**必须**创建一个 SSH 容器。主机上的 SSH 无法与容器通信。

```bash

     HOST SYSTEM
    +-----------------------------------------------------------------+
    |                                 +-------------------+           |
    |                                 |                   |           |
    |                                 |  SSHD ON HOST     |           |
    |                                 +-------------------+           |
    |                                                                 |
    |                                                                 |
    |   DOCKER OVERLAY NETWORK (isolated environment)                 |
    | +-------------------------------------------------------------+ |
    | |                                                             | |
    | |    +----------------+         +--------------------+        | |
    | |    |                |         |                    |        | |
    | |    |  SSH Container |         | Database Container |        | |
    | |    |                +-------->+                    |        | |
    | |    +-----^----------+         +--------------------+        | |
    | |          |                                                  | |
    | +-------------------------------------------------------------+ |
    |            |                                                    |
    +-----------------------------------------------------------------+
                 |
                 |
                 |
       +-----------+
       |    YOU    |
       +-----------+
```
