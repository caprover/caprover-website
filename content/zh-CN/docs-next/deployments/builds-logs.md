- CapRover 在服务器上构建源, 除非你提供预建的图像 。
- 监视应用程序的第一个失败的构建命令的部署输出 。
- 一个构建可能因为缺少文件,一个坏的Docker文件,没有依赖性,或者没有充足的RAM或磁盘而失败.

- 一旦图像建立,Docker更新了应用服务.
- 如果容器退出,健康检查失败,或返回502,则单独检查服务或应用日志。
- 配置的容器 HTTP 端口必须匹配进程的监听端口.

- 对于重构,使用CI在CapRover服务器外构建和推动图像,然后部署该图像.
- 对于已停止的部署, 请先收集失败的构建日志、 服务状态和最近的应用日志 。 [解决问题的部署](../troubleshooting/index.md).

## 版本和回滚

- CapRover 为一个应用程序记录图像版本.
- 从应用程序的部署历史中选择一个先前部署的版本来回滚回其图像.
- 在恢复交通前检查结果并应用健康.

- 倒转 **没有** 恢复较早的环境变量、域、体积内容或数据库计划。
- 如果更新版本更改了持久性数据,则确认旧图像在回滚前仍然兼容.
- 保存足够的图像历史或注册访问权限以获取您想要恢复的版本 。

健康检查和更新设置会影响申请在推出过程中的表现. 见 [健康检查和零下调部署](../scaling/index.md) 用于提供规划。
