One Dockerfile, two deployments

Your photo app has a Dockerfile that copies in the source. With the platform installed, how do you ship it today and update it tomorrow?

CapRover

First release
Create a web app and sign in with caprover login. Commit a captain-definition pointing to ./Dockerfile. Run caprover deploy and select the app and branch; the VPS builds the uploaded commit.
Next code change
Commit the change and run caprover deploy -d from the same directory to reuse your choices. The domain and HTTP settings stay with the app.
CLI deployment guide

Coolify

First release
Push the project to a Git repository. In a Coolify project and environment, create an application from the repository, select the branch and Dockerfile build pack, and deploy. The checkout provides the files for COPY.
Next code change
Push to that branch and redeploy, or enable automatic deployments. With a Git integration that supports previews, a pull request can get its own URL.
Dockerfile deployment guide

Dokploy

First release
Create an Application in a project environment. Select the Dockerfile build type and its path, then use the ZIP upload source to deploy the project directory from your computer.
Next code change
Upload a new ZIP for the same application. If you prefer to push commits, use a Git source instead; use a Compose resource if the stack definition belongs in the repository too.
Application sources and ZIP uploads
1 GiB

SMALL-SERVER FRIENDLY

CapRover documents a minimum of 1 GiB RAM and 5 GiB free disk. Coolify lists 2 GB RAM, 2 CPU cores and 10 GB free disk, and suggests 1 GB RAM for budget installations. These are setup figures; builds and apps need headroom. Dokploy recommends 2 GB RAM and 30 GB disk.

These are published installation requirements, not runtime benchmarks. Size your server for your apps, builds, and storage.
